# Overview

This detection identifies reconnaissance activity targeting Linux SSH services.

Attackers commonly perform network scanning before attempting exploitation. Tools such as Nmap can generate repeated SSH connection attempts, invalid protocol messages, and pre-authentication connection failures.

The detection analyzes SSH daemon logs to identify suspicious connection patterns associated with reconnaissance activity.

---

# Detection Objective

The objective of this detection is to identify:

- SSH service reconnaissance
- Network mapping activity
- Port scanning attempts
- Early-stage attacker behavior

The detection provides visibility into:

- Source attacker IP
- Target Linux host
- Target service
- Number of suspicious SSH connection attempts
- Detection timeline

# SPL Detection

```spl
index=linux_logs sourcetype=linux_secure "sshd" 
("Connection closed" OR "Bad protocol version" OR "Disconnecting" OR "preauth")

| rex field=_raw "by (?<src_ip>\d+\.\d+\.\d+\.\d+) port (?<src_port>\d+)"

| rex field=_raw "from (?<src_ip>\d+\.\d+\.\d+\.\d+) port (?<src_port>\d+)"

| rex field=_raw "invalid user (?<targeted_user>\S+)"

| rename host as target_system

| rename splunk_server as target_ip

| eval target_port="22 (SSH)"

| eval targeted_user=coalesce(targeted_user,"None (Pre-auth Scan)")

| stats 
min(_time) as detection_time,
count

by src_ip,
target_ip,
target_system,
target_port,
targeted_user

| fieldformat detection_time=strftime(detection_time,"%Y-%m-%d %H:%M:%S")

| eval threat_score=if(count>5,
"Medium - Reconnaissance Scan",
"Low - Normal Noise")

| table 
detection_time,
src_ip,
target_ip,
target_system,
target_port,
targeted_user,
count,
threat_score
```

# Detection Logic Explanation

## 1. Monitor SSH Pre-Authentication Activity

The detection monitors SSH events generated before authentication.

Examples:

```
Connection closed

Bad protocol version

preauth
```

These events often appear during scanning activity.

---

## 2. Extract Source Information

The detection extracts:

```
Source IP

Source Port

Target Host

Target Service
```

Example:

```
Source:

192.168.50.40


Target:

192.168.50.30


Service:

SSH
```

---

## 3. Identify Abnormal Activity

The detection evaluates the number of suspicious SSH events.

A high number of:

```
pre-authentication connections
```

from a single source indicates possible reconnaissance.

---

# Incident Response Actions

Recommended actions:

1. Validate the scanning source.
2. Determine whether scanning is authorized.
3. Block suspicious sources if required.
4. Review exposed services.
5. Investigate follow-up authentication attempts.
6. Harden SSH configuration.

---

# False Positives

Possible legitimate activity:

- Vulnerability scanners
- Security assessments
- Monitoring systems
- Administrator troubleshooting

Validation should consider:

- Source IP reputation
- Scanning frequency
- Maintenance schedules
