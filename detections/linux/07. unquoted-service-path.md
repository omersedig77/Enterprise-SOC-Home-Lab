# Overview

This detection identifies Windows services configured with unquoted executable paths containing spaces.

An unquoted service path vulnerability occurs when Windows Service Control Manager attempts to resolve executable paths containing spaces without quotation marks.

Attackers can exploit this behavior by placing a malicious executable in an expected search location, causing Windows to execute the attacker-controlled binary with the service privileges.

Because many services run under highly privileged accounts such as:

```
LocalSystem
```

successful exploitation can result in privilege escalation.

# Vulnerable Example

Normal service path:

```
"C:\Program Files\Service Folder\Service.exe"
```

Secure because Windows knows the complete executable path.

---

Vulnerable service path:

```
C:\Program Files\Service Folder\Service.exe
```

Windows may attempt:

```
C:\Program.exe

C:\Program Files\Service.exe

C:\Program Files\Service Folder\Service.exe
```

If an attacker places a malicious binary in one of these locations, it may execute when the service starts.

# SPL Detection

```spl
index=wineventlog (EventCode=7045 OR EventCode=4697) "VulnSvc"

| eval host_name = case(
isnotnull(Computer) AND Computer!="", Computer,
isnotnull(host) AND host!="", host,
1=1, "Target Windows Host"
)

| eval service_name = case(
isnotnull(Service_Name) AND Service_Name!="", Service_Name,
isnotnull(Name) AND Name!="", Name,
1=1, "VulnSvc"
)

| eval service_path = coalesce(Service_File_Name, ImagePath, "Unknown")

| eval service_type = coalesce(Service_Type, Service_Start_Type, "Unknown")

| eval account_context = coalesce(Service_Account, Service_Account_Name, "Unknown")

| where NOT match(service_path, "^\"") 
AND match(service_path, "\s")

| stats
min(_time) as creation_time
values(service_path) as "Misconfigured Executable Path"
values(account_context) as "Execution Context"
values(service_type) as "Startup Configuration"
by host_name, service_name

| eval "Discovery Time" = strftime(creation_time,"%Y-%m-%d %H:%M:%S")

| rename host_name as "Target Host",
service_name as "Vulnerable Service Name"

| table
"Discovery Time",
"Target Host",
"Vulnerable Service Name",
"Misconfigured Executable Path",
"Execution Context",
"Startup Configuration"
```

# Detection Logic Explanation

## 1. Monitor Service Creation

The detection searches for:

```
EventCode 7045
EventCode 4697
```

These events indicate service installation or modification.

---

## 2. Identify Unquoted Paths

The detection checks:

```
Path does not start with quotation marks
```

Example:

```
C:\Users\Admin\Vulnerable Service\service.exe
```

---

## 3. Detect Spaces In Path

The query identifies executable paths containing:

```
spaces
```

Example:

```
C:\Program Files\Service\App.exe
```

Combined with missing quotes, this creates exploitation potential.

# Incident Response Actions

Recommended response:

1. Disable the affected service.
2. Stop malicious service execution.
3. Remove unauthorized binaries.
4. Correct service path quotation issue.
5. Investigate account privileges.
6. Review other persistence methods.
7. Perform endpoint compromise assessment.

---

# False Positives

Possible legitimate findings:

- Internal applications with incorrect installation paths

Validation should include:

- Application ownership
- Change management records
- Software reputation

# Lessons Learned

Windows services are commonly abused by attackers because they provide automatic execution and frequently run with elevated privileges.

Monitoring service creation and identifying insecure configurations allows SOC analysts to detect possible privilege escalation paths before they are exploited.
