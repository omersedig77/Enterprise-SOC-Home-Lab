# Overview

This detection identifies high-volume failed SSH authentication attempts against Linux systems.

Attackers commonly perform SSH brute-force attacks to obtain valid credentials by repeatedly attempting different username and password combinations.

The detection monitors Linux authentication logs and identifies repeated failed login attempts originating from the same source IP address.

---

# Detection Objective

The purpose of this detection is to identify:

- Automated SSH password guessing
- Credential attack attempts
- Unauthorized access attempts
- External reconnaissance targeting SSH services

The detection provides visibility into:

- Source IP address
- Target Linux system
- Targeted username
- Number of failed attempts
- Attack timeframe

# SPL Detection

```spl
index=linux_logs sourcetype=linux_secure "Failed password"
| rex field=_raw "for (?<targeted_user>.*) from (?<src_ip>\d+\.\d+\.\d+\.\d+) port (?<src_port>\d+)"
| eval targeted_user = replace(targeted_user, "invalid user ", "")

| rename host as target_system
| rename splunk_server as target_ip
| eval target_port = "22 (SSH)"

| stats count, min(_time) as first_failed_login, max(_time) as last_failed_login by src_ip, target_ip, target_system, target_port, targeted_user
| where count > 10

| fieldformat first_failed_login = strftime(first_failed_login, "%Y-%m-%d %H:%M:%S")
| fieldformat last_failed_login = strftime(last_failed_login, "%Y-%m-%d %H:%M:%S")

| eval threat_score = "High - Active SSH Brute Force"
| sort - count
| table first_failed_login, last_failed_login, src_ip, target_ip, target_system, target_port, targeted_user, count, threat_score
```

# Detection Logic Explanation

## 1. Monitor Failed SSH Authentication

The detection searches Linux authentication logs for:

```
Failed password
```

These events indicate unsuccessful SSH authentication attempts.

---

## 2. Extract Attack Information

The query extracts:

```
Source IP

Target Username

Target System

SSH Port
```

Example:

```
Attacker:

192.168.50.40


Target:

192.168.50.30


Service:

SSH Port 22
```

---

## 3. Apply Threshold

The detection triggers when:

```
Failed attempts > 10
```

from the same source within the detection window.

This helps identify automated password guessing activity.

# Alert Configuration

## Severity

```
Medium
```

## Trigger Condition

The alert triggers when a single source IP generates more than 10 failed SSH authentication attempts against a Linux endpoint.

Example:

```
Source IP:

192.168.50.40


Target User:

admin


Failed Attempts:

15
```

This indicates possible SSH brute-force activity requiring investigation.

# Investigation Workflow

When this alert triggers:

---

# 1. Identify Source IP

Review:

```
src_ip
```

Determine:

- Internal or external source
- Known administrative system
- Previous malicious activity

---

# 2. Review Targeted Accounts

Analyze:

```
targeted_user
```

Look for:

- Existing users
- Disabled accounts
- Privileged accounts
- Common username guessing patterns

---

# 3. Check Successful Authentication

Search for:

```
Accepted password
```

Determine whether brute force resulted in compromise.

Example follow-up query:

```spl
index=linux_logs sourcetype=linux_secure "Accepted password"
```

---

# 4. Review Firewall Activity

Correlate with:

```
firewall index
```

Investigate:

- Source communication
- Allowed SSH traffic
- Blocked connections

---

# Incident Response Actions

Recommended response:

1. Validate whether activity is malicious.
2. Identify affected user accounts.
3. Review successful SSH logins.
4. Disable compromised accounts if required.
5. Reset credentials.
6. Block attacker IP at firewall.
7. Review additional attacker activity.

---

# False Positives

Possible legitimate activity:

- Administrator password mistakes
- Automated management tools
- Security testing
- Vulnerability assessments

Validation should consider:

- Source ownership
- Time of activity
- User identity
- Previous authentication history
