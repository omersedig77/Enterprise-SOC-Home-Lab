# Overview

This detection identifies successful SSH authentication after previous failed login attempts from the same source IP address.

A successful login following multiple failed attempts is a strong indicator that an attacker may have successfully compromised an account through brute-force activity.

The detection correlates failed and successful SSH authentication events to identify possible account compromise.

---

# Detection Objective

The purpose of this detection is to identify:

- Successful brute-force attacks
- Compromised Linux accounts
- Unauthorized SSH access
- Attacker access after credential guessing

The detection provides visibility into:

- Attacker IP address
- Target Linux host
- Compromised username
- Number of failed attempts
- Successful authentication time

# SPL Detection

```spl
index=linux_logs sourcetype=linux_secure ("Failed password" OR "Accepted password")
| rex field=_raw "(?<auth_status>Failed|Accepted) password for (invalid user )?(?<targeted_user>\S+) from (?<src_ip>\d+\.\d+\.\d+\.\d+) port (?<src_port>\d+)"

| rename host as target_system
| rename splunk_server as target_ip
| eval target_port = "22 (SSH)"

| stats
    count(eval(auth_status="Failed")) as total_failed_attempts,
    count(eval(auth_status="Accepted")) as total_successful_logins,
    values(targeted_user) as targeted_users_list,
    min(_time) as first_seen,
    max(_time) as last_seen
    by src_ip, target_ip, target_system, target_port

| where total_failed_attempts > 0 AND total_successful_logins > 0

| fieldformat first_seen = strftime(first_seen, "%Y-%m-%d %H:%M:%S")
| fieldformat last_seen = strftime(last_seen, "%Y-%m-%d %H:%M:%S")

| eval threat_score = "CRITICAL - Brute Force Success / Host Compromised"

| table first_seen, last_seen, src_ip, target_ip, target_system, target_port, targeted_users_list, total_failed_attempts, total_successful_logins, threat_score
```

# Detection Logic Explanation

## 1. Monitor SSH Authentication Events

The detection monitors:

```
Failed password
Accepted password
```

events from Linux authentication logs.

---

## 2. Correlate Failed and Successful Logins

The detection groups events by:

```
Source IP

Target Host

SSH Service
```

and calculates:

- Failed login count
- Successful login count
- Attack timeframe

---

## 3. Identify Possible Compromise

The alert triggers when:

```
Failed attempts > 0

AND

Successful login exists
```

from the same source.

This indicates that an attacker may have successfully guessed valid credentials.

# Incident Response Actions

Recommended response:

1. Confirm unauthorized access.
2. Identify compromised account.
3. Terminate active SSH sessions if required.
4. Reset compromised credentials.
5. Remove unauthorized access mechanisms.
6. Review attacker commands.
7. Block attacker IP through firewall.
8. Collect evidence for investigation.

# False Positives

Possible legitimate scenarios:

- User mistyped password before successful login
- Administrator troubleshooting
- Automated scripts with incorrect credentials

Validation should consider:

- Source IP reputation
- Login time
- User behavior
- Previous authentication history
