# Overview

This detection identifies high-frequency failed SSH authentication attempts against Linux systems.

Attackers commonly perform automated password guessing attacks against exposed SSH services in an attempt to obtain valid credentials.

The detection monitors failed SSH authentication events and identifies source IP addresses generating abnormal authentication failures.

---

# Detection Objective

The objective of this detection is to identify:

- SSH password spraying
- Automated brute-force attacks
- Unauthorized authentication attempts
- External reconnaissance against SSH services

The detection provides visibility into:

- Attacker source IP
- Target Linux endpoint
- Target username
- Number of failed attempts
- Attack timeline

# SPL Detection

```spl
index=linux_logs sourcetype=linux_secure "Failed password"

| rex field=_raw "for (?<targeted_user>.*) from (?<src_ip>\d+\.\d+\.\d+\.\d+) port (?<src_port>\d+)"

| eval targeted_user = replace(targeted_user,"invalid user ","")

| rename host as target_system

| rename splunk_server as target_ip

| eval target_port="22 (SSH)"

| stats 
count,
min(_time) as first_failed_login,
max(_time) as last_failed_login

by src_ip, target_ip, target_system, target_port, targeted_user

| where count > 10

| fieldformat first_failed_login=strftime(first_failed_login,"%Y-%m-%d %H:%M:%S")

| fieldformat last_failed_login=strftime(last_failed_login,"%Y-%m-%d %H:%M:%S")

| eval threat_score="High - Active SSH Brute Force"

| sort - count

| table 
first_failed_login,
last_failed_login,
src_ip,
target_ip,
target_system,
target_port,
targeted_user,
count,
threat_score
```

# Detection Logic Explanation

## 1. Monitor Failed SSH Authentication

The detection searches:

```
Failed password
```

events inside Linux authentication logs.

These events represent unsuccessful SSH login attempts.

---

## 2. Extract Attack Information

The query extracts:

```
Source IP

Target username

Target system

SSH port
```

Example:

```
Attacker:

192.168.50.40


Target User:

root


Service:

SSH Port 22
```

---

## 3. Apply Threshold Detection

The detection triggers when:

```
More than 10 failed SSH attempts
```

are observed from the same source IP.

This reduces noise from normal user mistakes while identifying automated attacks.

---

# Investigation Workflow

When this alert triggers:

---

## 1. Identify Source

Review:

```
src_ip
```

Determine:

- Internal system
- External host
- Known administrator workstation

---

## 2. Review Target Account

Analyze:

```
targeted_user
```

Look for:

- root attempts
- privileged accounts
- service accounts
- invalid users

---

## 3. Check Successful Authentication

Search:

```
Accepted password
```

after the failed attempts.

Example:

```
Failed password x30

+

Accepted password

=

Possible compromise
```

---

## 4. Review Additional Activity

Investigate:

```
sudo commands

Shell activity

Cron modifications

File changes

Network connections
```

# Incident Response Actions

Recommended actions:

1. Confirm whether the source IP is authorized.
2. Block malicious source IP if required.
3. Review compromised accounts.
4. Reset affected credentials.
5. Disable unnecessary SSH exposure.
6. Review SSH configuration.
7. Investigate post-authentication activity.

---

# False Positives

Possible legitimate events:

- Users entering incorrect passwords
- Automated scripts with outdated credentials
- Monitoring tools
- Misconfigured applications

Validation should consider:

- Number of attempts
- Source location
- Account targeted
- Time of activity

# Lessons Learned

SSH brute-force attacks are one of the most common threats against Linux systems.

Monitoring authentication failures provides early visibility into attacker activity and allows SOC analysts to investigate suspicious access attempts before account compromise occurs.
