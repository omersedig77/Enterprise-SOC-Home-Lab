# Overview

This detection identifies successful SSH authentication events that occur after one or more failed authentication attempts from the same source IP address.

A successful login following repeated failed attempts is a strong indicator of a possible brute-force attack resulting in account compromise.

The detection correlates:

- Failed SSH authentication attempts
- Successful SSH login events
- Source IP address
- Target system
- Target account

---

# Detection Objective

The objective of this detection is to identify:

- SSH brute-force attacks
- Successful unauthorized access
- Compromised Linux accounts
- External attacker authentication attempts

The detection provides visibility into:

- Attacker IP address
- Target Linux system
- Target username
- Authentication timeline
- Number of failed attempts before success

# SPL Detection

```spl
index=linux_logs sourcetype=linux_secure ("Failed password" OR "Accepted password")

| rex field=_raw "(?<auth_status>Failed|Accepted) password for (invalid user )?(?<targeted_user>\S+) from (?<src_ip>\d+\.\d+\.\d+\.\d+) port (?<src_port>\d+)"

| rename host as target_system

| rename splunk_server as target_ip

| eval target_port = "22 (SSH)"

| stats
count(eval(auth_status="Failed")) as total_failed_attempts,
count(eval(auth_status="Accepted")) as total_successful_logins,
values(targeted_user) as targeted_users_list,
min(_time) as first_seen,
max(_time) as last_seen

by src_ip, target_ip, target_system, target_port

| where total_failed_attempts > 0 AND total_successful_logins > 0

| fieldformat first_seen = strftime(first_seen,"%Y-%m-%d %H:%M:%S")

| fieldformat last_seen = strftime(last_seen,"%Y-%m-%d %H:%M:%S")

| eval threat_score="CRITICAL - Brute Force Success / Host Compromised"

| table first_seen,
last_seen,
src_ip,
target_ip,
target_system,
target_port,
targeted_users_list,
total_failed_attempts,
total_successful_logins,
threat_score
```

# Detection Logic Explanation

## 1. Monitor SSH Authentication Activity

The detection searches Linux authentication logs for:

```
Failed password
```

and:

```
Accepted password
```

These events represent unsuccessful and successful SSH authentication attempts.

---

## 2. Extract Authentication Details

The query extracts:

```
Source IP

Username

Authentication Status

Target Host
```

Example:

```
Source:

192.168.50.40


User:

admin


Status:

Accepted password
```

---

## 3. Correlate Failed and Successful Logins

The detection triggers when:

```
Failed SSH attempts

+

Successful SSH login

+

Same source IP
```

are observed together.

This indicates a possible successful brute-force compromise.

## Trigger Condition

The alert triggers when a source IP generates failed SSH authentication attempts and later successfully authenticates to the same Linux host.

Example:

```
Source IP:

192.168.50.40


Failed Attempts:

15


Successful Login:

1

Ubuntu Endpoint
```

# Incident Response Actions

Recommended actions:

1. Validate whether the account was compromised.
2. Disable or reset the affected account.
3. Terminate unauthorized SSH sessions.
4. Review attacker commands.
5. Remove persistence mechanisms.
6. Investigate additional compromised accounts.
7. Review firewall activity from the source IP.

---

# False Positives

Possible legitimate activity:

- User forgot password multiple times
- Automated administration tools
- Misconfigured applications

Validation should consider:

- Source location
- User account
- Time of activity
- Approved administrative activity

# Lessons Learned

SSH is a common attack surface in Linux environments.

Combining authentication failure monitoring with successful login correlation provides valuable detection capability against brute-force attacks and compromised credentials.

This detection demonstrates how SOC analysts can identify the transition from attempted access to successful compromise.
