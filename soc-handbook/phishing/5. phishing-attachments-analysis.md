# Phishing Attachment Analysis

## Overview

Malicious attachments are one of the most common phishing techniques used by attackers to deliver malware, steal credentials, or gain initial access to an organization.

Attackers commonly use:

- Microsoft Office documents
- PDF files
- ZIP archives
- Executable files
- Script files
- Disk image files
- Shortcut files

The objective of attachment analysis is to determine:

- Is the file malicious?
- What malware behavior does it perform?
- What systems may have been affected?
- What indicators should be blocked?
- What response actions are required?

- Isolated analysis system

# Common Malicious Attachment Types

---

# Executable Files

Examples:

```
.exe
.dll
.scr
.com
```

Attackers may disguise malware as:

- Software updates
- Security tools
- Documents
- Invoices

Example:

```
Invoice_2026.exe
```

Suspicious indicators:

- User was not expecting software
- Unknown publisher
- Downloaded from email
- Execution from temporary folders

---

# Microsoft Office Documents

Examples:

```
.doc

.docm

.xls

.xlsm

.pptm
```

Attackers commonly use:

- Macros
- Embedded scripts
- Exploit payloads
- External links

---

# Step 2 - Calculate File Hash

A hash creates a unique fingerprint of a file.

Common hashes:

```
MD5

SHA1

SHA256
```

SHA256 is commonly used for malware identification.

Example:

```
File:

invoice.exe


SHA256:

a8f45c9d92........
```

---

# Why Hashes Matter

Hashes allow analysts to:

- Search threat intelligence databases
- Identify known malware
- Detect repeated campaigns
- Create detection rules

# Step 3 - Static Analysis

Static analysis examines a file without executing it.

The analyst reviews:

- File metadata
- Strings
- Headers
- Embedded objects
- Digital signatures

---

# File Metadata

Review:

- File name
- File size
- Creation date
- Publisher
- Digital signature

Suspicious example:

```
Publisher:

Unknown


Created:

2 hours ago
```

---

# Strings Analysis

Strings can reveal:

- URLs
- IP addresses
- Commands
- File paths
- Malware names

Example:

```
http://malicious-domain.com/payload.exe

powershell.exe

cmd.exe
```

---

# Digital Signature Analysis

Check:

- Is the file signed?
- Who signed it?
- Is the certificate trusted?

Suspicious:

```
Signature:

Invalid
```

# Step 7 - YARA Analysis

YARA rules identify malware based on patterns.

Example:

```
rule Suspicious_PowerShell_Malware
{
    strings:

    $powershell = "powershell.exe"

    $download = "DownloadString"

    condition:

    all of them
}
```

---

SOC teams use YARA to:

- Identify malware families
- Scan suspicious files
- Create detection capabilities

# SOC Response Actions

Depending on severity:

- Block file hash
- Block malicious domain
- Remove phishing email
- Isolate affected endpoint
- Reset compromised accounts
- Investigate lateral movement
- Update detection rules

---

# Key Takeaways

Attachment analysis is a critical SOC analyst skill because phishing attachments frequently represent the first stage of compromise.

A complete investigation combines:

- File analysis
- Threat intelligence
- Sandbox analysis
- Endpoint telemetry
- Network investigation
- IOC extraction

Proper attachment analysis allows defenders to identify malware campaigns, contain threats, and prevent additional compromise.
