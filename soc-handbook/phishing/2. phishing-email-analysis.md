# Phishing Email Analysis

## Overview

Phishing email analysis is the process of investigating suspicious emails to determine whether they are malicious, identify attacker techniques, extract Indicators of Compromise (IOCs), and understand the potential impact on the organization.

SOC analysts analyze multiple components of an email including:

- Sender information
- Subject line
- Email body
- Links
- Attachments
- Email headers
- Authentication results
- Threat intelligence results
- User interaction history

The goal is to answer:

- Is this email malicious?
- Who received it?
- Did anyone interact with it?
- What indicators should be blocked?
- What response actions are required?

# Step 1 - Collect Email Evidence

Before analysis begins, preserve the original email.

Required evidence:

- Original email file (.eml or .msg)
- Full email headers
- Sender address
- Recipient list
- Timestamp
- Attachments
- Embedded links
- User interaction details

Avoid analyzing only screenshots because important technical information may be missing.

---

# Step 2 - Analyze the Sender Information

The sender is one of the first indicators an analyst should review.

---

# Display Name Analysis

Attackers commonly impersonate trusted organizations by changing the display name.

Example:

```
Display Name:

Microsoft Security Team


Email Address:

security-alerts@gmail-support.com
```

The display name appears legitimate, but the actual email address is suspicious.

---

## Things to Check

Look for:

- Brand impersonation
- Misspelled domains
- Random characters
- Free email providers
- Recently created domains

Examples:

Legitimate:

```
security@microsoft.com
```

Suspicious:

```
security@microsoft-support123.com
```

Suspicious:

```
microsoft.security.alert@gmail.com
```

---

# Sender Domain Analysis

Validate:

- Domain ownership
- Domain age
- Reputation
- DNS records
- Previous malicious activity

Common suspicious indicators:

```
micros0ft.com

paypa1-support.com

secure-login-update.xyz
```

Common attacker techniques:

## Typosquatting

Creating domains similar to legitimate organizations.

Example:

```
google.com

goog1e.com
```

---

## Homoglyph Attacks

Replacing characters with visually similar characters.

Example:

```
apple.com

аpple.com
```

(The second domain uses a different character.)

---

# Step 3 - Analyze Subject Line

Attackers use psychological manipulation to force users into quick decisions.

Common phishing subjects:

```
Your account has been suspended

Urgent password reset required

Payment failed

Invoice attached

Security alert

Mailbox storage exceeded

Final warning
```

---

# Suspicious Subject Indicators

## Urgency

Examples:

```
Immediate action required

Your account will be deleted today

Respond within 30 minutes
```

Purpose:

Prevent users from carefully analyzing the email.

---

## Fear

Examples:

```
Unauthorized login detected

Your account has been compromised

Legal action required
```

Purpose:

Create panic.

---

## Authority Impersonation

Examples:

```
CEO Request

IT Administrator

Security Department
```

Purpose:

Exploit trust.

---

## Financial Pressure

Examples:

```
Urgent payment request

Updated banking information

Invoice overdue
```

Common in Business Email Compromise attacks.

---

# Step 4 - Analyze Email Content

Review the body of the email.

Look for:

## Credential Requests

Legitimate organizations rarely request passwords.

Examples:

```
Please verify your password.

Confirm your account credentials.

Enter your Microsoft password.
```

---

## Grammar and Formatting

Indicators:

- Poor grammar
- Unusual wording
- Incorrect company branding
- Strange formatting
- Generic greetings

Example:

```
Dear customer,

Your account need verification immediately.
```

---

## Social Engineering Techniques

Attackers commonly use:

### Urgency

"Act immediately."

### Fear

"Your account will be disabled."

### Curiosity

"You have received a confidential document."

### Authority

"Your manager requested this."

### Reward

"You won a prize."

---

# Step 5 - Analyze Links

Never directly open suspicious links.

Analyze:

- URL structure
- Domain reputation
- Redirects
- Destination website
- Domain age

---

# Suspicious URL Indicators

## IP Address URLs

Example:

```
http://192.168.50.40/login
```

Legitimate organizations usually do not send authentication links using IP addresses.

---

## URL Shorteners

Examples:

```
bit.ly

tinyurl.com

t.co
```

Attackers use these to hide the final destination.

---

## Fake Login Pages

Common targets:

- Microsoft 365
- Google
- Banking websites
- VPN portals

Indicators:

- Fake authentication pages
- Credential submission forms
- Look-alike domains

---

## Suspicious Domains

Examples:

```
office365-login-security.com

microsoftverify-account.xyz
```

---

# Step 6 - Analyze Attachments

Attachments are a common malware delivery method.

Review:

- File type
- File name
- Hash
- Embedded content
- Macros
- Execution behavior

---

# Suspicious Extensions

High-risk extensions:

```
.exe

.scr

.bat

.cmd

.ps1

.js

.vbs

.iso

.img

.docm

.xlsm
```

---

# Suspicious Attachment Names

Examples:

```
Invoice.pdf.exe

Payment_Details.zip

Resume.docm

Password_Update.xlsm
```

---

# Double Extension Attacks

Example:

```
document.pdf.exe
```

The attacker attempts to make the file appear harmless.

---

# Office Macro Attacks

Common files:

```
.docm

.xlsm
```

Malicious macros may execute:

- PowerShell
- Command prompt
- Malware downloaders

After extracting IOCs, search the organization.

Look for:

## Email Security

- Who received the email?
- Who opened it?
- Who clicked the link?

---

## Endpoint

Check:

- Process execution
- File creation
- PowerShell activity
- Network connections

Sources:

- EDR
- Sysmon
- Windows Event Logs

---

## Network

Check:

- DNS queries
- Firewall connections
- Proxy logs

# Determining the Verdict

After analysis, classify the email.

---

# Malicious

Indicators:

- Suspicious sender
- Malicious attachment
- Credential harvesting page
- Threat intelligence matches
- User interaction detected

Action:

- Block indicators
- Remove emails
- Investigate affected users

---

# Suspicious

Indicators:

- Some malicious characteristics
- Requires additional investigation

Action:

- Escalate
- Perform deeper analysis

---

# Benign

Indicators:

- Legitimate sender
- Valid authentication
- No malicious indicators

Action:

- Close investigation

# Key Takeaways

Effective phishing analysis requires combining human behavior analysis with technical investigation.

A SOC analyst must understand both:

- Social engineering techniques used by attackers
- Technical indicators left behind during an attack

A complete phishing investigation does not stop at identifying a malicious email. Analysts must determine:

- Who was targeted
- Whether users interacted
- What indicators were involved
- Whether compromise occurred
- What response actions are required
