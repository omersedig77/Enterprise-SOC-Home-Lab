# Phishing Fundamentals

## Overview

Phishing is a social engineering technique where attackers attempt to manipulate users into performing actions that benefit the attacker.

The objective is usually to:

- Steal credentials
- Deliver malware
- Gain initial access
- Perform financial fraud
- Collect sensitive information
- Establish persistence inside an environment

Unlike traditional technical attacks that exploit software vulnerabilities, phishing primarily targets the human element by abusing trust, urgency, fear, curiosity, or authority.

Phishing remains one of the most common initial access techniques used against organizations.

---

# Why Attackers Use Phishing

Attackers use phishing because:

- Employees are often easier to compromise than technical defenses.
- A successful phishing email can provide valid credentials.
- Stolen credentials can bypass security controls.
- Phishing can deliver malware without exploiting vulnerabilities.
- It provides an entry point for larger attacks.

A successful phishing attack can lead to:

```
Phishing Email
       |
       |
       ▼
User Interaction
       |
       |
       ▼
Credential Theft / Malware Execution
       |
       |
       ▼
Initial Access
       |
       |
       ▼
Privilege Escalation
       |
       |
       ▼
Lateral Movement
       |
       |
       ▼
Data Theft
```

# Phishing Attack Lifecycle

A typical phishing campaign follows these stages:

## 1. Reconnaissance

Attackers collect information about the target.

Information collected may include:

- Employee names
- Job roles
- Email addresses
- Company structure
- Technology used by the organization
- Public social media information

Common sources:

- LinkedIn
- Company websites
- Data leaks
- Public documents

---

## 2. Preparation

The attacker creates phishing infrastructure.

Examples:

- Fake domains
- Fake login pages
- Malicious attachments
- Email templates
- Command and Control infrastructure

Examples:

Legitimate domain:

```
microsoft.com
```

Fake domain:

```
micros0ft-security.com
```

---

## 3. Delivery

The phishing message is sent to the victim.

Delivery methods:

- Email
- SMS
- Phone calls
- Social media messages
- QR codes

---

## 4. User Interaction

The victim performs an action.

Examples:

- Clicking a malicious link
- Opening an attachment
- Entering credentials
- Enabling macros
- Installing software

---

## 5. Exploitation

The attacker uses the user's action.

Examples:

- Credential theft
- Malware execution
- Remote access installation
- Session hijacking

---

## 6. Post-Compromise Activity

After gaining access, attackers may:

- Create persistence
- Escalate privileges
- Move laterally
- Collect data
- Exfiltrate information

# Types of Phishing

---

# Email Phishing

## Description

The most common phishing technique where attackers send malicious emails pretending to be legitimate organizations or individuals.

Examples:

- Fake Microsoft password reset
- Fake invoice
- Fake security alert
- Fake delivery notification

Common indicators:

- Urgent language
- Suspicious sender domain
- Unexpected attachments
- Suspicious links
- Requests for credentials

---

# Spear Phishing

## Description

A targeted phishing attack against a specific individual or organization.

Unlike general phishing, spear phishing is customized.

Attackers may include:

- Employee names
- Company information
- Internal terminology
- Current projects

Example:

A finance employee receives:

```
Updated Q4 Invoice - Please Review
```

The email contains information gathered from public sources.

---

# Whaling

## Description

A phishing attack targeting high-value individuals.

Targets:

- CEOs
- Executives
- Directors
- Administrators

Common goals:

- Financial fraud
- Access to sensitive information
- Business Email Compromise

Example:

An attacker impersonates the CEO and requests an urgent wire transfer.

---

# Business Email Compromise (BEC)

## Description

A social engineering attack where attackers impersonate trusted business accounts.

Common scenarios:

- Fake CEO requests
- Fake vendor payment changes
- Fake invoice requests

Indicators:

- Payment urgency
- Changed banking information
- Unusual communication style
- Requests for secrecy

---

# Clone Phishing

## Description

Attackers copy a legitimate email and modify it with malicious content.

Example:

Original:

```
Your invoice is attached.
```

Modified:

```
Updated invoice attached.
```

The attachment contains malware.

---

# Smishing

## Description

Phishing performed through SMS messages.

Examples:

```
Your package delivery failed.
Click here to reschedule.
```

Common goals:

- Credential theft
- Malware installation
- Financial fraud

---

# Vishing

## Description

Voice-based phishing using phone calls.

Attackers may impersonate:

- Banks
- IT support
- Government agencies
- Company executives

Common techniques:

- Creating urgency
- Requesting verification codes
- Asking for credentials

---

# QR Code Phishing (Quishing)

## Description

Attackers use QR codes to redirect victims to malicious websites.

Common examples:

- Fake MFA setup
- Fake password reset
- Fake payment pages

Risks:

- Mobile devices may bypass email security controls.
- Users cannot easily inspect QR destinations.

---

# MFA Fatigue Attacks

## Description

Attackers repeatedly send MFA approval requests hoping the victim accepts one.

Attack flow:

```
Password Obtained
        |
        |
        ▼
Repeated MFA Requests
        |
        |
        ▼
Victim Accepts Request
        |
        |
        ▼
Account Compromised
```

Detection indicators:

- Multiple MFA requests
- Login from unusual locations
- Impossible travel events

---

# OAuth Phishing

## Description

Attackers trick users into granting malicious applications access to accounts.

Instead of stealing passwords, attackers abuse authorization.

Examples:

- Fake Microsoft OAuth applications
- Fake Google integrations

Possible access:

- Email
- Cloud storage
- User information

---

# Phishing Indicators

SOC analysts should look for:

## Email Indicators

- Suspicious sender address
- Mismatched display name
- Unexpected attachments
- Urgent requests
- Grammar mistakes
- Threats or pressure
- Requests for credentials

---

## Domain Indicators

- Newly registered domains
- Typosquatting
- Random characters
- Suspicious TLDs

Examples:

```
micr0soft.com

paypa1-login.com

secure-account-update.xyz
```

---

## Attachment Indicators

Suspicious file types:

```
.exe
.scr
.js
.vbs
.bat
.cmd
.ps1
.iso
.img
.docm
.xlsm
```

---

## Link Indicators

Suspicious URLs:

- URL shorteners
- IP address URLs
- Fake login pages
- Redirect chains
- Look-alike domains

# SOC Analyst Role in Phishing Investigations

A SOC analyst should be able to:

- Validate whether an email is malicious.
- Analyze email headers.
- Investigate sender reputation.
- Analyze URLs.
- Analyze attachments.
- Extract Indicators of Compromise (IOCs).
- Search the environment for related activity.
- Determine affected users.
- Recommend containment actions.

---

# Key Takeaways

Phishing is one of the most common initial access techniques used by attackers.

A successful SOC investigation requires analysts to combine:

- Email analysis
- Threat intelligence
- Endpoint telemetry
- Network visibility
- IOC investigation
- User activity monitoring

Understanding phishing fundamentals provides the foundation for detecting, investigating, and responding to phishing attacks.
