# Phishing Link Analysis

## Overview

Malicious links are one of the most common techniques used in phishing campaigns.

Attackers use links to:

- Steal credentials
- Deliver malware
- Redirect users to fake login pages
- Track victims
- Establish initial access
- Download malicious payloads

A SOC analyst must be able to safely investigate suspicious URLs without interacting with malicious infrastructure.

The goal of URL analysis is to determine:

- Is the URL malicious?
- What infrastructure is behind it?
- Has anyone accessed it?
- What indicators should be blocked?
- Are additional systems compromised?

# Step 1 - Collect the URL

Collect the original URL from:

- Email body
- Email headers
- Security gateway logs
- Browser history
- Proxy logs
- User report

Example:

```
https://secure-login-update-example.com/authentication
```

Do not open suspicious links directly from a workstation.

---

# Step 2 - Analyze URL Structure

A URL consists of multiple components.

Example:

```
https://login.microsoft-security-update.com/account/reset
```

Breakdown:

```
https://
|
Protocol


login
|
Subdomain


microsoft-security-update.com
|
Domain


/account/reset
|
Path
```

---

# Protocol Analysis

## HTTP

Example:

```
http://example.com
```

HTTP traffic is unencrypted.

Suspicious when used for:

- Login pages
- Credential submission
- Banking websites

---

## HTTPS

Example:

```
https://example.com
```

HTTPS only provides encryption.

Important:

HTTPS does NOT mean the website is legitimate.

Attackers commonly use HTTPS certificates for malicious domains.

---

# Domain Analysis

The domain is one of the most important investigation points.

Check:

- Domain reputation
- Registration date
- Ownership
- DNS records
- Previous abuse

---

# Suspicious Domain Indicators

## Recently Registered Domains

Attackers frequently create temporary domains for campaigns.

Example:

```
microsoft-security-login2026.com
```

Created:

```
2 days ago
```

High risk indicator.

---

## Typosquatting

Attackers create domains similar to legitimate websites.

Examples:

Legitimate:

```
microsoft.com
```

Fake:

```
micros0ft.com
```

---

Examples:

```
google.com

go0gle.com


paypal.com

paypa1.com
```

---

## Brand Impersonation

Example:

Legitimate:

```
apple.com
```

Suspicious:

```
apple-security-verification.com
```

---

## Suspicious TLDs

Attackers commonly use inexpensive domains.

Examples:

```
.xyz

.top

.click

.live

.shop

.site

.online
```

A suspicious TLD alone does not confirm malicious activity but requires investigation.

---

# Step 3 - URL Path Analysis

The path can reveal attacker objectives.

Examples:

## Credential Harvesting

```
/login

/signin

/verify

/account

/password-reset
```

---

## Malware Delivery

```
/download

/update

/install

/file.exe
```

---

## Tracking Victims

Examples:

```
?id=12345

?email=user@example.com
```

---

# Step 4 - Analyze URL Parameters

Attackers may include information in parameters.

Example:

```
https://fake-login.com/login?user=victim@example.com
```

Possible purposes:

- Tracking victims
- Campaign identification
- Credential harvesting

---

# Step 5 - URL Shortener Analysis

Attackers use URL shorteners to hide malicious destinations.

Examples:

```
bit.ly

tinyurl.com

t.co

goo.gl
```

Example:

Visible:

```
https://bit.ly/abc123
```

Actual destination:

```
https://malicious-domain.com/login
```

---

SOC analysts should expand shortened URLs before analysis.

---

# Step 6 - Redirect Analysis

Attackers often use multiple redirects.

Example:

```
Email Link

↓

shortener.com

↓

tracking-domain.com

↓

fake-login-page.com
```

Analyze:

- Initial URL
- Final destination
- Number of redirects
- Intermediate domains

---

# Step 7 - Fake Login Page Analysis

Credential harvesting pages commonly imitate:

- Microsoft 365
- Google
- Dropbox
- Banking portals
- VPN portals

---

Indicators:

- URL does not match official domain
- Login page requests unusual information
- Poor branding
- Different language
- Suspicious certificates
- Credential submission to unknown domain

---

Example:

Fake:

```
https://microsoft-login-security.xyz
```

Legitimate:

```
https://login.microsoftonline.com
```

- Sandboxes

- Threat intelligence platforms

- ANY.RUN
- Hybrid Analysis
- URLScan

# SOC Analyst Recommendations

When malicious URLs are confirmed:

Actions may include:

- Block domain
- Block URL
- Block associated IP addresses
- Remove phishing emails
- Reset compromised credentials
- Investigate affected endpoints
- Search for additional victims

---

# Key Takeaways

URL analysis is a critical phishing investigation skill.

A malicious link investigation requires more than checking whether a website loads. Analysts must evaluate:

- Domain reputation
- URL structure
- Redirect behavior
- Threat intelligence
- User activity
- Endpoint and network telemetry

Proper URL analysis allows SOC teams to identify phishing campaigns, prevent credential theft, and reduce attacker access.
